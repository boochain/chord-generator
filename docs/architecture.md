# 和声引擎 v4 架构

v4 把和弦生成从“挑模板再循环”改成**分层规划 + 候选生成 + 软约束打分采样**。所有代码仍在 `src/engine.js`，构建后内联进单文件 `index.html`，没有外部依赖。

## 1. 总流程

```
resolve(设置) ─▶ buildProg(和声规划) ─▶ applyComplexity(和弦性质) ─▶ pickArr(编配) ─▶ finalize(声部排列) ─▶ validate(乐理校验)
                                                                                              │不通过
                                                       严格声部进行重排 → 退回密集排列 → 换种子（≤40 次）◀─┘
```

## 2. 设置解析 `resolve`

- 风格、情绪、调式、调性、速度、复杂度沿用 v3 逻辑。
- 小节数默认从 `[8, 8, 8, 12, 16, 16]` 抽取（v3 只有 8/16）。
- 拍号：风格支持多种拍号时，约 6% 的概率选非 4/4（保证默认仍以 4/4 为主）。
- 和声节奏 `hr`（每小节 0.5/1/2 个和弦）按风格权重抽取。

## 3. 和声规划器 `buildProg`

### 3.1 曲式层（section → phrase）
`pickForm(nP)` 按乐句数选曲式：2 句 `AA / AA' / AB`，3 句 `AAB / ABA / AA'B / ABC / ABA'`，4 句 `AABA / ABAB / ABAC / AA'BA' / ABCA / ABCD …`，更长的进行由多个 4 句组拼接并加入变奏句。循环型风格（Lo-fi、嘻哈、电子、氛围、放克、雷鬼）更偏向 `AA…`，少用 C/D。

### 3.2 乐句层：候选生成 `phraseCands`
每个新字母（A、B、C…）生成约 30 个候选，来源：

| 来源 | 说明 | 先验 |
|---|---|---|
| 风格语料 `tpl` | `CORPUS[M/m][风格大类]`（约 400 条，带出处注释），4 和弦模板 40% 概率旋转 | 0.5 |
| 子风格自带 `own` | 子风格定义里的 `tpl`（v4 为弗拉门戈、死亡金属、恐怖、雷鬼顿、流行朋克、探戈、斯卡等大幅扩充） | 0.9 |
| 通用语料 `glob` | 跨风格常用进行 | 0.1 |
| 拼接 `splice` | A 的前半 + B 的后半，接缝必须在风格模型里出现过 | 0.3 |
| 功能代理 `sub` | 同功能替换：I↔vi/iii、IV↔ii/vi、i↔♭III/♭VI … | 0.3 |
| 马尔可夫 `markov` | 风格可变阶模型游走（温度 0.9–1.4） | 0 |

和声节奏为 2 时，模板会被“拉长”：部分和弦延长一格，部分插入经过/辅助和弦（插入的和弦必须同时能接在前后和弦的语料中）。所有候选必须通过 `tplLegal`（逐和弦 `chordIssues`）。

### 3.3 风格语言模型 `lmFor`
- 3/2/1/0 阶插值回退（权重 0.25/0.35/0.32/0.08），模板按循环计数（末尾接回开头）。
- 训练数据：风格大类语料 ×1、子风格自带 ×1.5、通用语料 ×0.3。
- 数字级数（`1 5 6 4`）先用 `skelR` 按大/小调参照映射成罗马数字，所以数字写法与罗马写法共享统计。

### 3.4 打分 `scoreCand`（软约束）
```
score = 1.2·LM 平均对数概率 + 来源先验
      + Σ 情绪特征权重(MOOD_FEAT)·特征 + Σ 拍号特征权重(METER_FEAT)·特征
      + 复杂度匹配（0 级惩罚副属/减/借用，≥2 级奖励副属/七和弦）
      − 0.35·相邻重复（循环型风格除外） − 0.6·（不同和弦 < 3）
      − 2.2·在“最近生成”记忆中出现次数 − 1.5·与本曲已用乐句相同
      − 1.5·起始功能不符
```
特征包括：借用比例、小调式开头、属功能比例、变格、♭VI/♭VII、副属、ii–V、减和弦、IV、iv、iii、七和弦比例、和弦变化率。然后按 softmax（τ = 0.7）采样，而不是取最高分，因此高分进行常见但不垄断。

### 3.5 终止层
- 末句：`applyCadence` 按权重抽取终止类型（正格、ii–V–I、IV–V–I、变格、小调变格、后门、♭VI–♭VII–I、重属、♭VII→i、安达卢西亚、iv–V–i），风格和情绪调整权重；调式音乐用调式特征终止。
- 中间句：B/C 句或 30% 的 A 句会改成半终止（停在 V）或阻碍进行（V→vi / V→♭VI），其余保持开放。
- 变奏句 A'：`variantOf` 保留轮廓，替换 1 个和弦（多在句尾）。

### 3.6 反重复记忆
`RECENT`（每个风格最近 48 个乐句骨架）只在“不指定种子”的生成中生效，所以连续点击不会重复，而指定种子的结果仍可复现。重新生成（`regenerate`）把当前歌曲已有的乐句作为记忆，并且传递情绪和拍号。

## 4. 编配层 `pickArr`
每首歌独立抽取，并写入 `song.arr`（会被序列化）：
- **伴奏型**：风格本身的伴奏型权重 3，`PAT_ALT` 中的近亲型各 1（例如 pulse → strum/arp/block，lofi → arp/pad/boom）。界面选“随风格”时就用这首歌的伴奏型。
- **排列**：`voicingW(style)` 决定 密集 / 开放（drop-2、展开）/ 混合 的概率。`openVoicings` 枚举每个音级一个音、相邻 ≤ 12、总跨度 13–19 的排列，与密集排列一起进入 Viterbi；偏好通过每个和弦的小额代价表达，声部进行规则仍然优先。
- **旋律轮廓**：拱形、倒拱形、上行、下行、波浪、自由。按 4 小节乐句内的位置决定方向（85% 遵循），但仍以级进为主，强拍落在和弦音上。

## 5. 歌曲扩展
- 段落计划不变（前奏 – 主歌 – 导歌 – 副歌 …）。
- 第二段主歌必定变奏（第一段长主歌也有 35% 概率）：保留前半句种子动机，后半句做功能代理替换，或用风格语料重新配和声。
- 导歌、桥段、副歌延伸部分的 `buildProg` 共享已用乐句骨架作为记忆，段落之间互相避让。

## 6. 校验
`validate` 的硬规则见 `docs/theory-rules.md`。v4 唯一的规则变化是排列间距：从“总跨度 ≤ 12”放宽为“相邻 ≤ 12、总跨度 ≤ 19”。生成后不通过时依次：严格声部进行重排（同一排列偏好）→ 严格重排为密集排列 → 换种子；所有测试中通过率 100%。

## 7. 度量与回归
- `node tools/diversity.js [N] [out.json]`：每风格 N 次生成的唯一进行比例、4-gram 数、熵、前 10 占比、编辑距离、排列/伴奏型种类，参数敏感度，连续点击重复，扩展段落区分度。
- `test/diversity.test.js`（纳入 `npm test`）以带余量的阈值防止回退。报告见 `docs/diversity-report.md`。
